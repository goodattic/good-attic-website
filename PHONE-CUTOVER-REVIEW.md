## The two production `0018` migrations

The filenames collide numerically but are different direct SQL imports into the same D1 database (`good-attic-angi-jobber-router`, ID `934d7ad9-cba8-4cb4-9494-1e9980b7c403`):

1. `work/qualified-phone-manual-link/migrations/0018_quo_call_capture_stage.sql` was applied October 2. It created `quo_call_capture_stage` for Utah, St. Louis, and Kansas City and its caller index. The capture-first release record says it has no `d1_migrations` row.
2. `migrations/0018_short_ad_request_notes.sql` was applied with the October 7 short ad form release. Its migration proof records creation of `short_ad_request_notes`, which keeps note retry separate from lead delivery.

Do not assume a numeric `0018` means either table is absent, and do not run blanket `migrations apply`. Before future SQL, take a new D1 backup, inspect the live schema and registry read-only, compare row counts, and apply only the specifically reviewed SQL file. Proposed future order: `0019_quo_call_attributions_kc.sql` (a main-ledger table rebuild that needs a separate data-preservation review), `0020_qualified_phone_request_claims.sql` (after the required ledger/auth schema), `0021_quo_call_capture_missed_topic.sql` (after the market capture table), then `0022_quo_national_call_capture_stage.sql` (National call-only table). The older, unapplied `0010` ledger migration must not run after `0019` because it would remove Kansas City support. Use the next unused number for any new migration; never reuse `0018`.

2. **Stop the new behavior.** Set the new missed-call alerts off and stop the manual-request matching shadow/upload path. Keep existing website lead alerts, failed-lead alerts, Data Manager uploads, and three-market call capture as they were. Reconcile in-flight Quo receipts and broker writes before restoring automatic Requests; a caller should not get both an auto-created and a manually created Request.
3. **Restore the webhook.** PATCH only `resourceIds` on subscription `40213` to its saved pre-cutover ordered array. 8. **Reconcile the switch window.** Compare Quo call IDs on all four numbers against capture rows, missed-call alert operations, and Jobber Requests. Resolve holds or duplicate Requests with staff.
